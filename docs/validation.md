# Проверка и воспроизведение submission-v3

`python scripts/reproduce.py` последовательно выполняет все эксперименты, собирает PDF и исполняет Jupyter Notebook. Общий `OZON_RUN_ID` связывает эту серию. Повторные CPU-замеры следует выполнять при свободной системе.

`python scripts/verify_submission.py` запускает регрессии, выполняет и сохраняет Jupyter Notebook, проверяет структуру PDF. `results/verification.json` содержит фактическое число проверок по группам, время, среду и SHA исходников. Короткий интеграционный replay входит в тесты: изображения → геометрическое назначение → производственный контракт → финализация → долговечная доставка → запись намерения WCS.

## Происхождение результатов

Каждый новый эксперимент сохраняет `metadata`: CPU, ОС, архитектура, Python, версии пакетов, фактический Git SHA, признак изменений рабочей копии, SHA-256 исходников, параметры и полный конфиг с хешем. Модель CPU читается из ОС; при ограничениях среды допускается явный `OZON_CPU_MODEL`, происхождение поля сохраняется. Значение `unavailable` означает отсутствие доступного измерения.

Показатели PDF и README формируются из JSON. Сборка отвергает несовпадающий конфиг; `results/report_manifest.json` фиксирует SHA-256 всех входных результатов и журналов. Изменение результатов в регрессионном тесте меняет числа, подписи и выводы отчёта.

## Группы проверок

| Граница | Проверка |
|---|---|
| Происхождение захвата | Камера, scan/frame ID, сессия, коробка, все ожидаемые фрагменты, пропуски строк |
| Пространственные экземпляры | Два одинаковых кода в реальном синтетическом растре и две области коробок |
| Сессия и время | Повтор box_id в новой сессии; рестарт процесса; карантин после смены эпохи ОС |
| Получатель | Противоречивые статусы/коды/грани, повреждение журнала, конфликт тела, ACK с хешем |
| Сквозная обработка | Общий кадр двух коробок, пропуск полосы, повтор доставки, WCS и очистка |
| Общий конфиг | Два значения скорости: частота/строки, положение последнего наблюдения и срок |
| Длительная работа | 5000 треков с ограниченным количеством активных записей; очистка SQLite |
| Материалы | Подмена метрик, проверка конфигурации, PDF и исполненные ячейки Jupyter Notebook |

Нагрузочная серия включает три отдельных запуска пула и 24 значения на коробку, сложные углы и пустые наблюдения. Сохраняются все ошибки и просрочки. Генерация массивов входит во время обслуживания; реальный IPC/DMA и SDK камер требуют отдельного измерения.

CI на push проверяет форматирование, тесты, сборку PDF и Jupyter Notebook. Ручной workflow «Полное воспроизведение экспериментов» сохраняет полный набор артефактов на машине GitHub; её времена характеризуют среду runner.

PDF проверяется рендером всех страниц; локальные изображения проверки находятся в игнорируемой папке `output/qa/revision3`. Для поставки используйте тег `submission-v3` и его PDF. Предыдущая версия сохранена тегом `submission-v2`.
