# Шестистороннее чтение штрихкодов на конвейере

Вариант 2 тестового задания по Computer Vision для мастерской Ozon. **Автор: Карим Гимадиев.**

**[PDF-отчёт — 21 страница](output/pdf/ozon_cv2_report_ru.pdf)** · [Jupyter Notebook](notebooks/demo_ru.ipynb) · [Матрица 20 замечаний](docs/review_matrix.md) · [Рабочий контракт](docs/system_contract.md)

Четыре линейные камеры сканируют верх, дно и бока; две площадные камеры снимают торцы. Энкодер связывает изображения с движением. Локальный компьютер объединяет все уникальные значения и передаёт результат WCS для сортировки.

![Два состояния коробки при чтении торцов](docs/figures/layout.png)

## Быстрый запуск

Версия материалов — тег `submission-v2`. Python 3.12, CPU; установка зависимостей выполняется один раз.

```bash
git clone https://github.com/gimacorp/ozon-barcode-reader.git
cd ozon-barcode-reader
git checkout submission-v2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows активация: `.venv\Scripts\activate`.

```bash
python -m pytest -q
python -m barcode_reader calculate
python -m barcode_reader.replay
```

Ожидается: тесты пройдены, расчёты сохранены, сквозная демонстрация восстановила по 12 значений у двух коробок. Короткая проверка после установки занимает около 2 секунд на Apple M5. Детали проверки версии: [verification.json](results/verification.json).

Чтение сохранённого полного торцевого кадра:

```bash
python -m barcode_reader decode results/nominal_frame.png --formats Code128
```

Результат — JSON с символикой, текстом, исходными байтами и четырьмя углами. По умолчанию Code 128 и дополнительный вид +45°; `--formats Code128,DataMatrix,QRCode` меняет перечень. `--enhanced` добавляет CLAHE и увеличение ×2. CLI ограничивает отдельный процесс сроком 5 секунд; `--timeout` задаёт другое значение, включая старт и загрузку файла.

Ключ объединения — **символика + исходные байты**. Одинаковые физические наклейки дают одно уникальное значение. `capture_complete` проверяет все обязательные кадры/строки; `complete_set_verified: false` сохраняет неизвестность числа наклеек.

## Воспроизведение экспериментов

```bash
python scripts/engineering_review.py
python scripts/nominal_experiment.py
python scripts/ablation.py
python scripts/load_replay.py --boxes 12
python scripts/visual_evidence.py
python -m barcode_reader benchmark --boxes 60 --seed 20260909
python scripts/build_report.py
```

Ожидаемые результаты — в таблице выше. Номинальный прогон занимает несколько минут, факторное сравнение около минуты, нагрузочный replay около 30 секунд на измерительном компьютере. CPU-замеры запускать последовательно при свободной системе. Повтор обновляет результаты и тайминги; исходная версия сохраняется тегом. Для быстрого знакомства: `python -m barcode_reader benchmark --boxes 6 --output output/quick`.

Для экспериментального сравнения сохранены четыре комбинации «автоматические символики / Code 128 × исходная ориентация / дополнительный поворот 45°», а также отдельные добавления CLAHE и ×2. Политики K=1, K=2 и прикладная маска сравниваются на всём наборе. [Журнал](results/ablation_predictions.jsonl) сохраняет формат и байты каждого чтения по кадрам.

## Проектные параметры

| Параметр | Значение |
|---|---|
| Лента / скорость / интервал передних кромок | 650 мм / 1 м/с / 2 с |
| Коробка | 600 × 400 × 400 мм |
| Минимальный модуль / этикетка | 0,33 мм / до 78 × 25 мм |
| Лимит нагрузки | 24 уникальных значения, до четырёх этикеток на грань |
| Подача | Центр ±3 мм; yaw/pitch/roll ±0,5°; остальные допуски в контракте |
| Линейные камеры | 4 × Basler raL8192-80km; 12 кГц, 40 мкс, F/8 |
| Торцы | 2 × hr65MXGE; 9344 × 7000; 16 Гц; пять кадров, F/11 |
| Получение + обработка / доставка | 500 мс, включая 80 мс получения / 50 мс ACK |
| Доступное время после резервов | 635 мс |

Конфигурация: [conveyor.json](configs/conveyor.json). Полная [ведомость компонентов](docs/bom.json) содержит объективы, адаптеры, питание, триггеры и кабели. [Контракт](docs/system_contract.md) определяет геометрию назначения, полноту строк/кадров, независимость исходных данных, очередь EDF, аппаратную синхронизацию и обмен WCS.

## Что проверяет прототип

| Реализовано и проверено | Аппаратная интеграция |
|---|---|
| Декодирование, геометрия, физическая модель изображений | Настройка реальной оптики, света и направляющих |
| Контракт непрерывных строк и полного набора кадров | SDK, потери транспорта, аппаратные метаданные |
| Геометрическое назначение ROI и запрет повторного владельца | Калибровка и адаптер реального трекинга |
| CPU replay, модель EDF/очереди/отмены | Shared-memory DMA и watchdog постоянного пула |
| Долговечные SQLite Outbox / WCS, рестарты и повторы | HTTP-сервис и подтверждение исполнения от ПЛК |
| Проверка двух реальных иллюстраций | Собственная фотосерия и промышленная приёмка |

[Протокол фотосерии](docs/photo_protocol.md) и [печатные этикетки](docs/print_labels.html) подготовлены для следующего этапа. Съёмку выполняет человек с телефоном и распечатками; она отдельно дополняет доступные данные.

## Структура

```text
barcode_reader/  Декодер, оптика, геометрия, контракты, назначение, очередь и WCS
configs/         Расчётная конфигурация
scripts/         Эксперименты, визуальные доказательства и сборка PDF
tests/           Автоматические проверки по группам
results/         Числа, журналы предсказаний, manifest и исходные иллюстрации
docs/            Контракт, матрица замечаний, ведомость, рисунки, текст отчёта
notebooks/       Демонстрационный Jupyter Notebook
output/pdf/      Итоговый отчёт
```

Приёмка начинается с минимального X на торцах при F/11, граничных допусков подачи и кромок нижнего обзора; затем проверяются нагрузка и связь на выбранном IPC.
